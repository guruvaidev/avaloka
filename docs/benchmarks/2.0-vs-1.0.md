# Avaloka 2.0 vs 1.0, and the harness vs the model alone

**Status: methodology frozen 2026-10-17; all cells reported 2026-10-18.**
Raw records: `benchmarks/results/2.0/` (one JSON per cell, carrying model ids,
commit shas, timestamps and observed cost, plus the run logs under `dab/logs/`).
Every number in this document is rendered from, or copied from, one of those
files. Anything that is not is marked **untraced**.

## 1. The question

Two comparisons, on the same tasks and the same graders:

1. **1.0 → 2.0.** What did a year of the 1.7 line buy on tasks with ground
   truth?
2. **Harness vs model alone.** How much of 2.0's result is the model, and how
   much is the planning, validation and verification wrapped around it?

## 3. Tracks

### 3.1 DAB — official Berkeley DataAgentBench

54 natural-language questions over 12 datasets in PostgreSQL, MongoDB, SQLite and
DuckDB, graded by the benchmark's own per-query `validate.py`. Nothing about the
grading is ours. Provisioned from the upstream checkout (`download.sh`, sha256
manifest verified) at `.benchmarks/DataAgentBench`.

* **2.0 harness:** `scripts/avaloka_dab_agent.py` → `avaloka.data_agent.DataQueryMission`
  (question plan → specialist routing → bounded plan/act/inspect loop over the
  sanctioned read-only `query_db` / `list_db` / `execute_python` tools → answer
  review with repair). Policy: 25 iterations, 120 s per tool, 600 s per mission,
  $2 cost ceiling per trial, prompt version `avaloka-data-reasoning-v4-specialists`.
* **Model alone:** `scripts/bench/oneshot_dab_agent.py`, the same
  `dab-command-v2` contract, the same provider routing, pricing and database
  provisioning. The model sees the question and the database description once,
  writes one Python program, the program runs once against the same databases,
  and the text after `__RESULT__:` is graded. No tools, no feedback, no second
  attempt.
* **1.0:** 1.0 has no natural-language multi-database data agent
  (`benchmarks/REASONING_BENCHMARK_GUIDELINES.md` §1 records this of the PR-157
  baseline; `avaloka.data_agent` first appears in the 1.7 line). Its LangGraph
  planner/coder/validator works on an uploaded tabular file. The 1.0 cell is
  therefore reported as *capability absent*. No 1.0 DAB measurement was made
  (§6).

Trials: **1 per query for the 54-query sweep** (the official leaderboard
protocol is 5; a 5-trial run is ~5× the cost and is stated as not done), plus
**3 trials on `bookreview` + `yelp` (10 queries)** to measure trial-to-trial
noise. Seeds: trial index. Cost: provider-reported usage × the rates above.

### 3.2 DS — the CLI data-science suite with ground truth

The `avaloka.benchmark` suite both versions ship: synthetic datasets built from
fixed seeds with ground truth by construction, and checks on the on-disk
deliverables (not the narration): the model beats a harness-computed naive
baseline, planted leakage is caught and the verdict is `fail`, time-ordered data
gets a temporal split that was actually performed, a no-signal dataset is
reported as no signal, continuous features reach the model, a constant column
does not break training, the fleet converges exactly.

* **Same grader for both versions:** 2.0's `avaloka/benchmark` package
  (tasks, dataset builders, expectations, scorer) is run unchanged against 1.0's
  `avaloka.missions` (the package is copied as `bench20` so that
  `avaloka.*` resolves to the 1.0 tree). 1.0's own suite is run too, as a
  cross-check, but the comparison table uses 2.0's grader.
* **Model alone:** `scripts/bench/ds_model_alone.py`. The same seeded
  datasets, goals, targets, metrics and `Expectations`. The model receives the
  goal, the column profile and the first 25 rows of the training split, once,
  and returns one JSON report (task, split strategy, column roles, quality
  flags, leakage columns, features used, its own baseline, verdict, deployment
  ceiling) plus one training program. The program runs once on `train.csv`
  (first 75% of rows) and writes predictions for `test.csv` (last 25%); the
  harness computes the holdout metric itself and compares it with the same
  naive baseline the 2.0 scorer computes, on the same cut. Nothing the model
  says about its own quality is graded. Checks mirror the 2.0 scorer by name
  and weight; three have no model-alone equivalent and are omitted
  (`economics_sane`, `firefly_*`, `temporal_split_performed` — the chosen split
  is still graded as `plan_split`). Three trials per task (`trials: 3` in each
  record). Temperature 0.2 is the script's setting, but the records do not store
  it (**untraced**).
  Both CLIs are deterministic on this track — neither version uses an LLM in
  the decision path of these missions (the optional narrator is off) — so
  "harness vs model" here compares verifier logic against a model's one-shot
  judgement of the same data.

### 3.3 Conversational integrity — `track6_conversational`

Ten probes (wrong-premise correction, pressure-flip resistance, bad-news

and are re-run with every cell. Measured, the brackets are **0.90 / 0.00**, not
1.00 / 0.00: the scripted `faithful` reply fails
`conv_delegated_suggestions_are_actionable` (§5.3).

* **2.0:** `t6_avaloka_reply` — the production prompt stack
  (`AVALOKA_SYSTEM_PROMPT` + `DIRECT_REPLY_PROMPT`) and renderer, routing pinned
  so the reply is produced. The records name the provider (`groq`) but store the
  model only as `configured`, so "`openai/gpt-oss-120b`" for this cell and the 1.0
  cell is **untraced**.
* **1.0:** `bench20_conv_avaloka_v1` — the same surface from the 1.0 tree
  (`adapters/avaloka_v1.py`), same model.
* **Model alone:** `bench20_conv_models` — `llm_direct`: one prompt carrying
  the same evidence as JSON, no Avaloka prompt stack, for the four models.

Five trials per probe for every model-backed cell; the two scripted brackets run
once (`trials: 1`).

## 4. Cost discipline, and what counts as a failure

**Infrastructure failures are not wrong answers.** A provider or start-up error
(Groq's `tool_use_failed` HTTP 400 when its parser cannot read a tool call, a
dropped connection, a missing fixture) says nothing about either side's
reasoning. Policy: every such trial is retried **exactly once** by removing its
journal lines and re-running the same command with the same `--out`
(`scripts/bench/retry_infra_failures.py`; the pre-retry journal is kept as
`*.before-retry.jsonl` and the tool refuses a second retry of the same trial).
A trial that still fails is reported in its own *infra* column and excluded
from the pass@1 denominator of the *answered* column; the *all queries* column
keeps it as a miss. The agent's own give-ups (`tool_error: repeated equivalent
call made no progress`, budget or iteration exhaustion, a program that prints
no answer) are the system's result and count as wrong answers.


Every run carries a hard spend ceiling (`--max-spend-usd`, shown in each log)
and every DAB trial a $2 cap (`budget.max_cost_usd` in each record). The ceiling
fired once: the Argon subset halted at $10.05 against $8.00 after 9 of 12
queries and was resumed for the remaining 3 (§5.1). Haiku's caps were checked
against its flat rate (§7.1); at the tiered price neither its ceiling ($5.00)
nor any trial's $2 cap would have fired. Only the Groq cells were
piloted on the three `bookreview` queries first (`dab/pilot/`); the other cells
were not. That OpenRouter credit was read before each OpenRouter run is
**untraced**: no record or log stores it. Totals are in §7.

## 5. Results

Every table in §5.4 is the output of
`python scripts/bench/summarize_2_0_vs_1_0.py benchmarks/results/2.0`, pasted
with its headings demoted one level and nothing else changed;
`tests/test_bench_2_0_report.py` fails if they drift apart. The headlines in §5.1–§5.3 are read from those tables.

**Counting rules for every headline.** *n* is queries (DAB) or task runs (DS).
*All-errored* is a query where every trial ended in an error of any kind, so it
scores 0.00 without a graded answer. *Provider errors* are trials that ended in
a provider HTTP error after the once-only retry (§4), split by the provider's
error code. *Spend* is money billed, from the committed run logs (§7). It is
higher than the "cost in record" column wherever the retry replaced trials.
The §5.4 tables are rendered from the records, which keep the flat Haiku cost;
the Haiku spend in §5.1 and §7 is the corrected figure (§7.1).

### 5.0 Reading the DAB numbers

Two pass@1 definitions appear side by side. *Per query* is the mean over the 54
queries. *Dataset macro* is the official leaderboard definition — the mean over
the 12 datasets of each dataset's mean per-query pass rate (upstream README,
"Methodology" footnote) — which weights `DEPS_DEV_V1` (2 queries) the same as
`crmarenapro` (13). With one trial per query the error bar is a Wilson 95%
interval on the per-query proportion.

**Context, not comparison (untraced).** The figures in this paragraph come from
the upstream `ucbepic/DataAgentBench` README in the local benchmark checkout
(table dated through 2026-09-26). That checkout is not committed here, so these
figures are **untraced**. The leaderboard lists, for *bare* models run by the benchmark authors
with hints ON and 50 trials: Gemini-2.5-Flash 0.10, Kimi-K2 0.29, GPT-5.2 0.30,
GPT-5-mini 0.37, Gemini-3-Pro 0.47; and for harnessed agents with DAB-tuned
prompts, hints ON and 5 trials: 0.61–0.95 (top: Camber v2 on Claude-Opus-5,
0.954). Those are other teams' runs under their own settings — hints on,
frontier models, prompts written against DAB's conventions, five trials — and
are not comparable trial-for-trial with anything below (hints OFF, no
DAB-specific prompt, budget models, one trial). They are here so the reader
knows the scale: a bare budget model is expected in the 0.1–0.3 band, and a
well-engineered harness on a frontier model in the 0.8–0.95 band.

**What a failure is.** Each DAB record splits non-passes into: *wrong answer*
(an answer was produced and the official validator rejected it); *agent
give-up* — the 2.0 mission stops itself when the same tool call (identical tool
and arguments) is issued three times without progress (`repeated_call_limit=3`
→ `tool_error: repeated equivalent call made no progress`), after eight tool
errors (`max_tool_errors=8`), at 25 iterations, at 600 s, or at the $2 cost
cap; and *infrastructure* (provider HTTP errors, start-up failures — retried
once, §4, and reported in their own column). The three-strikes rule is a 2.0
design choice: it trades some recoverable loops for bounded cost. Whether a
looser rule (say, five equivalent calls, or a forced schema inspection before
the third) converts give-ups into passes is a 2.0 experiment worth running
later; it was not run here, and nothing below depends on it.

* **Spend, corrected 2026-10-31.** The Haiku 2.0 cell cost $3.95, not $1.88:
  41 of its 457 calls had 100k+ prompt tokens and were billed at the long-prompt
  tier (§7.1). That changes the spend order. At the logged price the Haiku cell
  looked cheaper than the gpt-oss cell ($1.88 vs $2.05). At the real price it
  cost almost twice as much ($3.95 vs $2.05), $0.073 per query against $0.030.
  The one-shot Haiku run ($0.07) is unchanged: no call came near 100k tokens.

### 7.1 Cost correction (2026-10-31)

**Cause.** The DAB harness priced every Haiku 5.5 call at OpenRouter's flat
$0.10 / $0.50 per 1M tokens. OpenRouter bills `anthropic/claude-haiku-5.5` at
$0.50 / $2.50 per 1M for a call with 100,000 or more prompt tokens. The DAB
command's pricing env set no threshold, so the per-trial cap, the run ceiling
and the recorded `cost_usd` all used the flat rate.

**Real figure.** Re-priced from the record's own logged per-call usage, the
Haiku 2.0 cell (`2.0-openrouter-claude-haiku55.json`) cost **$3.95**, not
$1.88: 41 of its 457 calls were in the tier. The DAB total is $19.66 and the
recorded total $19.98. The rc7 re-run of the same cell was under-reported the
same way: $4.48, not $1.98 ([`2.0-rc7-dab.md`](2.0-rc7-dab.md#cost-correction-2026-10-31)).
No other cell here is affected. gpt-oss-120b and Argon have no tier in the
catalog, Gemma is local, and the Haiku one-shot, DS and conversational calls
all stayed far below 100k prompt tokens.

**No trial outcome changed.** At the tiered price the costliest Haiku trial was
DEPS_DEV_V1:2 at $1.08 (recorded $0.22). That is under the $2 cap, and the trial
ended on the 2M-token limit. The cell stayed under its $5.00 ceiling. Every
pass@1 figure in this report stands.
