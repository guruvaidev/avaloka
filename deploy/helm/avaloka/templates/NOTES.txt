MLflow requires a login (mlflow.auth). The Service is cluster-internal only. From a
workstation:
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "avaloka.fullname" . }}-mlflow {{ .Values.mlflow.port }}:{{ .Values.mlflow.port }}
then sign in as the user in MLFLOW_TRACKING_USERNAME with the password in
MLFLOW_TRACKING_PASSWORD, both in the Secret {{ include "avaloka.secretName" . }}:
  kubectl -n {{ .Release.Namespace }} get secret {{ include "avaloka.secretName" . }} -o jsonpath='{.data.MLFLOW_TRACKING_PASSWORD}' | base64 -d
(a script can export both variables instead; the mlflow client sends them).

{{- if (include "avaloka.rayAuthEnabled" $) }}

Ray requires a token (ray.auth, RAY_AUTH_MODE=token; Ray 2.52+ and KubeRay 1.6+).
Apply deploy/helm/ray/*.yaml after this release: they read the token from the
Secret {{ include "avaloka.rayAuthSecretName" . }}. The dashboard has no NodePort or LoadBalancer:
  kubectl -n {{ include "avaloka.rayNamespace" . }} port-forward svc/avaloka-raycluster-head-svc 8265:8265
and paste the token into the dashboard's login, or export RAY_AUTH_MODE=token and
RAY_AUTH_TOKEN for `ray job submit`:
  kubectl -n {{ include "avaloka.rayNamespace" . }} get secret {{ include "avaloka.rayAuthSecretName" . }} -o jsonpath='{.data.auth_token}' | base64 -d
